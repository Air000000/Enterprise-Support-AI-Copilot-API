## 能力核实与选择

查阅[阿里云官方结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)：
JSON Object 只约束有效 JSON，不保证字段/层级；JSON Schema 是另一种能力。
文档将非思考 Qwen3.5-Plus 系列列在 JSON Object 范围内，
严格 JSON Schema 支持列表没有 Qwen3.5-Plus。
因此没有文档依据把当前固定的 `qwen3.5-plus-2026-04-20`、
新加坡端点视为严格 Schema 可用；未用真实请求探测，也不声称已验证端点运行能力。
通用示例中的区域 URL 不证明某个快照支持 Schema。

保留固定模型/区域及 `json_object` 路线，**不增加 `json_schema` 请求参数或能力回退**，
不偷偷切换到支持名单中的其他模型。未来迁移模型需独立确认区域可用性、成本与新对照，
且结构合法永远不代替引用/语义验证。官方页面会更新，本记录是查阅当时的文档结论。

## 最小改动

实现见 [refusal_single_contract.py](../../refusal_single_contract.py)：

- 一个独立的 `v5.4_dev` system prompt，仅一个完整、可解析的最终 JSON 模板，
  不继承并叠加多代提示词/局部输出示例。明确三个根字段、引用对象/数组边界及重复键禁令。
- 澄清必要路径、可选分支、信息或链接、实际步骤、适用/因果桥接和固定版本审计。
  不把选中路径的必要未知条件“降格为可选”，不跳过同范围的真实冲突。
- 用户消息继续使用既有完整上下文、原顺序及 source-local 原始行号；
  严格解析器、全部状态、必需审计及确定性拒答门保持原样。

这是**提示词整理加语义澄清的组合候选**，不是只改结构的消融试验；
即使未来有变化，也不能仅归因为模板。现在没有真实预测，不能声称格式错误减少、
误拒/误放行改善或问题已修复。合成测试只验证消息、模板、引用边界及门行为。
刻意错误的可选 CONDITIONAL 仍然拒答，刻意错误的 NOT_REQUIRED 仍可能结构合法；
不靠读取理由、关键词白名单或丢弃条目来替模型改判断。
